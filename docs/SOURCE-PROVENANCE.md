# 来源与版权边界

这份文档记录独立插件项目的来源，避免将插件代码、游戏派生数据和示例配置混为一谈。

## 可验证的 Git 来源

独立项目最初从开发仓库 `Stronghold-Protocol` 的 `extension/` 目录拆分。

- 插件目录首次出现：`1a08e00`，标签 `v1.0.4`
- 独立项目拆分时使用的插件状态：`e78ac25`，标签 `v1.0.11`
- 独立项目的当前首个提交：`cd16c2a`

在可审计的开发仓库中，`v1.0.3` 没有 `extension/` 目录；`v1.0.4` 新增了 `manifest.json`、弹窗、页面注入脚本、策略解析器和目录快照。因此本项目包含的是插件代码，而不是游戏服务器、客户端渲染器或战斗逻辑。

## 文件分类

### 插件代码

包括：

- `core.js`
- `content.js`
- `popup.js`
- `popup.html`
- `popup.css`
- `popup-layout.js`
- `tools/`
- `test/`

这些文件按项目的 GPL-3.0-or-later 许可证发布。拆分和修改不会自动消除原有代码的版权或许可证义务。

### 游戏派生目录

`catalog.json` 包含干员 ID、名称、阶位和羁绊映射，用于把游戏页面可见名称匹配到策略规则。它是插件运行所需的轻量游戏派生数据，不等同于插件源代码，也不应被单方面声明为 GPL 代码。

### 示例配置

`default-config.json`、`yan-strategy.json` 和 `attention-notes.json` 是插件示例配置。配置中的游戏名称、干员 ID 和羁绊 ID 仍受其原始权利边界影响；配置中的策略说明文字则应按实际作者和贡献记录处理。

## 尚未完成的外部版本比对

测试目录 `D:\Software\Stronghold-Protocol` 被指定为运行测试场，本次审计没有读取或修改该目录。因此本项目尚未对该目录中的新版 `0.1.3` 做逐文件比较。

如果未来要证明独立项目与新版测试目录之间没有代码重合，应在隔离的审计副本中提供该版本的 Git 提交号，或仅提供需要比较的插件文件，然后执行哈希和差异审计。

在该比对完成前，本项目采用保守做法：插件代码继续使用 GPL-3.0-or-later，并明确记录已知来源，不对未知外部版本作“完全原创”声明。
